# 股票多因子建模与投资前景评价模型说明书

这份说明书不是代码说明，而是用尽量通俗的语言解释：这个股票多因子模型到底在做什么、为什么这样做、每一步怎么理解、最后结果应该怎么写进报告。

本文使用的实际结果主要来自 `outputs_optimized/` 目录，包括最终参数配置、实验日志、前向分步回归结果、PROMETHEE 结果、Top-K 回测结果、评级结果和偏好函数敏感性比较。

## 1. 一句话说明这个项目在做什么

用最简单的话说：

> 我们不是直接预测股票明天涨多少，而是根据公司基本面、宏观环境和模型评分，把同一季度的股票从好到差排队，然后选出排名靠前的一批股票，检验它们后续表现是否更好。

也就是说，本项目的核心不是问：

> “某只股票下一期一定涨多少？”

而是问：

> “在同一个季度里，哪些股票相对更值得关注？哪些股票更适合作为候选投资对象？”

所以本项目做的是一个“投资前景评价框架”。它包含几个连续步骤：

1. 用公司自身数据构造个股因子；
2. 用宏观经济和市场环境数据构造宏观因子；
3. 把个股因子和宏观因子相乘，构造 231 个宏微观综合因子；
4. 用移动窗口前向分步回归从 231 个因子中动态挑选变量；
5. 用入选因子生成股票排序分数；
6. 用熵权-PROMETHEE 计算投资前景值；
7. 构造 Hybrid Score 作为综合评分候选；
8. 按评分生成 13 级评级；
9. 用 Top-K 回测检验高分股票组合后续表现。

## 2. 为什么不能简单理解为收益率预测

很多人第一次看到“预测股票收益率”，会以为模型要精确回答：

> “A 股票下一期涨 3.2%，B 股票下一期涨 1.7%。”

但真实股票市场里，收益率受很多短期因素影响，例如市场情绪、政策消息、行业突发事件、资金流动、投资者预期等。这些因素很难完全被财务因子和宏观因子解释。因此，股票收益率的点预测通常非常 noisy，也就是噪声很大。

这里的“噪声”可以理解为：

> 结果里有很多随机波动，不完全由模型里的变量决定。

所以，即使一个模型的 `R²` 不高，甚至为负，也不一定说明它完全没有价值。

`R²` 是回归模型里常见的指标，意思是：

> 模型能解释真实收益波动的比例。

但是在股票选股任务中，我们更关心的是排序能力，而不是精确数值。举例来说：

> 如果模型不能准确预测 A 股票未来涨 3.2%、B 股票涨 1.7%，但能大致判断 A 比 B 更值得关注，这对选股仍然有意义。

因此，本项目更关注：

- `RankIC`：模型排名和真实收益排名是否一致；
- `Top-K 收益`：模型选出的前 K 只股票后续表现如何；
- `Sharpe`：组合承担单位风险能获得多少收益；
- `Alpha`：组合相对基准是否有超额收益；
- `评级分层`：高评级股票整体是否优于低评级股票。

换句话说，本项目的目标是“把股票排得更合理”，而不是“精确算出每只股票未来收益率”。

## 3. 数据从哪里来

本项目的数据可以分成两大类：个股因子和宏观因子。

### 3.1 个股因子

个股因子代表公司自身情况。可以把它理解成：

> 用一组数字描述一家公司质量、估值、成长和经营状态。

常见含义包括：

- 盈利能力：公司赚钱能力强不强；
- 成长能力：收入、利润是否增长；
- 现金流质量：公司是否真的收到现金，而不是只有账面利润；
- 估值水平：股票价格相对利润、净资产、现金流是贵还是便宜；
- 公司规模：公司市值、流通市值等；
- 运营效率：公司资产和收入使用效率如何。

但是，并不是所有个股字段都能进入模型。收益类字段不能作为解释变量，因为它们和标签非常接近，甚至可能直接包含未来收益信息。

本项目明确不进入模型的字段包括：

- `future_return_1q`；
- `月平均收益率`；
- `区间涨跌幅(1月)`；
- `区间涨跌幅(3月)`；
- `区间涨跌幅(6月)`；
- `股票编号`；
- `证券代码`；
- `证券名称`；
- `quarter_idx`；
- 其他 ID、收益类、标签类、meta 字段。

其中 `future_return_1q` 是正式标签，只能用于训练和事后检验，不能作为模型输入。

### 3.2 宏观因子

宏观因子代表市场大环境。可以理解为：

> 公司不只受到自身经营影响，也受到经济周期、货币环境、市场估值和风险偏好的影响。

本项目实际使用 11 个可识别宏观因子：

| 宏观因子 | 通俗理解 |
|---|---|
| `bm` | 市场账面市值比，可以理解为整体估值状态的一种描述 |
| `de` | 股利支付或股利相关指标，反映市场分红状态 |
| `dp` | 股息价格比，反映股息相对价格的水平 |
| `ep` | 盈利价格比，反映盈利相对价格的水平 |
| `infl` | 通胀水平，反映物价变化 |
| `itgr` | 工业或投资增长相关指标，反映经济活动变化 |
| `m2gr` | M2 货币增速，反映货币环境宽松或收紧 |
| `mtr` | 利率或期限相关变量，反映资金价格环境 |
| `ntis` | 净发行或融资相关指标，反映市场融资状态 |
| `svar` | 市场波动或风险水平 |
| `tms` | 期限利差，反映长短期利率差异 |

不用死记这些缩写。对本项目来说，它们的共同作用是：

> 描述股票所处的市场环境。

## 4. 为什么作业说 276 个综合因子，本文实际用 231 个

作业理论口径是：

> 23 个个股因子 × 12 个宏观因子 = 276 个综合因子。

但是实际做数据审计后发现：

1. 宏观数据中只有 11 个可稳定识别的宏观变量；
2. 第 12 个宏观因子没有清晰字段名、定义和可用数据；
3. 个股数据里有一些收益类字段，不能作为解释变量；
4. 如果为了凑数量把收益类字段放进模型，会造成数据泄漏；
5. 最终可稳定使用的是 21 个非收益型个股因子和 11 个宏观因子；
6. 因此实际构造 `21 × 11 = 231` 个宏微观综合因子。

这不是偷懒，而是为了保证：

- 不把未来收益信息放进模型；
- 不硬凑不存在或不可解释的变量；
- 结果可以复现；
- 符合作业中“不能数据泄漏”的要求。

| 项目 | 作业理论口径 | 实际数据口径 | 本文处理 |
|---|---:|---:|---|
| 个股因子 | 23 | 21 个非收益型因子 | 使用 21 个 |
| 宏观因子 | 12 | 11 个可识别因子 | 使用 11 个 |
| 综合因子 | 276 | 231 | 使用 231 个 |
| 收益类字段 | 未单独说明 | 存在 | 剔除 |

## 5. 什么是宏微观综合因子

宏微观综合因子就是：

> 把公司自身特征和宏观环境结合起来看。

公式是：

```text
composite_factor = 标准化后的个股因子 × 标准化后的宏观因子
```

举例来说，如果一个公司盈利能力很强，同时当前货币增速较高，那么：

```text
盈利能力 × M2 货币增速
```

可以理解为：

> 在当前货币环境下，盈利能力强的公司是否更有投资价值。

为什么要先标准化？

因为不同指标单位完全不一样。比如：

- 市盈率可能是几十倍；
- 现金流可能是几亿元；
- 通胀率可能是几个百分点；
- 市值可能是几百亿。

这些数字不能直接相乘。标准化的作用是把它们转换成相对可比较的分数，再构造交互因子。

本项目最终使用 231 个综合因子，全部来自：

```text
21 个非收益型个股因子 × 11 个宏观因子
```

## 6. 为什么要做前向分步回归

本项目有 231 个候选综合因子，但不能把它们全部塞进模型。

原因很简单：

- 因子太多，容易把噪声也当成规律；
- 因子之间可能高度相关；
- 模型会变得难解释；
- 样本数量有限，变量太多容易过拟合。

“过拟合”可以理解为：

> 模型把历史样本里的偶然现象记住了，但到新样本就不灵了。

前向分步回归的作用是：

> 从 231 个候选因子里，一步一步挑出当前窗口最有用的一小部分。

可以用一个生活化例子理解：

> 就像选队员打比赛，不是一开始把 231 个人全派上场，而是一轮一轮挑最能补强队伍的人。

几个关键概念：

| 概念 | 通俗解释 |
|---|---|
| 候选因子池 | 一开始可供选择的 231 个综合因子 |
| 残差 | 模型当前还没解释掉的误差 |
| 每一步选因子 | 找一个最能解释剩余误差的因子加入模型 |
| 停止条件 | 选够数量，或新增因子带来的提升很小 |
| 滚动选择 | 每个季度都重新用过去窗口选因子 |

本项目最终配置中，前向分步回归最多选择 12 个因子，使用 `residual_correlation` 作为选择目标。它的意思是：

> 每一步优先选择与当前残差最相关的因子。

## 7. 移动窗口是什么意思

移动窗口就是：

> 模型只用过去一段时间的数据来预测下一期，不偷看未来。

本项目时间切分固定为：

- train：`quarter_idx` 1-21；
- valid：`quarter_idx` 22-25；
- test：`quarter_idx` 26-30。

最终配置里：

```text
rolling_window = 12
```

这表示模型每次使用过去 12 个季度作为训练窗口。举例来说：

- 用第 1-12 季数据训练，预测第 13 季；
- 用第 2-13 季数据训练，预测第 14 季；
- 用第 3-14 季数据训练，预测第 15 季；
- 依此类推。

每往后一个季度，窗口就向前滚动一次。

这里最重要的原则是：

> 测试集只能最后检验，不能用来调参数。

也就是说，模型参数要根据训练集和验证集确定，测试集相当于期末考试，不能提前看答案。

## 8. 前向分步回归在本项目里输出什么

前向分步回归不是只输出一个收益预测值，它会输出一整套可解释结果：

1. 每个季度选中了哪些因子；
2. 每个因子的回归系数；
3. 每只股票的 `stagewise_pred`；
4. 每只股票在本季度的 `stagewise_rank`；
5. 每个季度的 `RankIC`；
6. 每个因子被选中的频率。

这些输出分别有不同用途：

- 入选因子用于解释“模型在看什么”；
- `stagewise_pred` 用于给股票排序；
- 高频入选因子可以进入 PROMETHEE 指标池；
- `RankIC` 用于判断排序是否有效。

当前优化结果中，前向分步回归高频入选因子包括：

| 高频因子 | 入选次数 | 简单说明 |
|---|---:|---|
| `composite_净资产收益率_TTM_x_ntis` | 10 | 净资产收益率与融资环境交互 |
| `composite_市净率PB_LF_x_svar` | 9 | 市净率与市场风险波动交互 |
| `composite_净资产收益率_TTM_x_itgr` | 8 | 净资产收益率与增长环境交互 |
| `composite_流通市值_x_svar` | 7 | 流通市值与市场波动交互 |

这说明模型不是固定看某一个指标，而是在不同季度动态筛选变量。

## 9. 什么是 RankIC

`RankIC` 衡量的是：

> 模型排名和真实收益排名是否一致。

举例来说，某季度有 A、B、C 三只股票。

如果模型排序是：

```text
A > B > C
```

之后真实收益排序也是：

```text
A > B > C
```

那么 RankIC 会比较高。

如果真实收益排序反过来：

```text
C > B > A
```

那么 RankIC 可能为负。

可以这样理解：

- `RankIC > 0`：模型有正向排序信号；
- `RankIC < 0`：模型排序可能反了；
- `RankIC 接近 0`：排序信号较弱。

当前优化结果中，前向分步回归平均 RankIC 为：

| 数据区间 | 平均 RankIC |
|---|---:|
| train | -0.0390 |
| valid | 0.1371 |
| test | 0.0649 |

这说明模型在验证集和测试集上有正向排序信号，但信号强度不能夸大。股票收益噪声很大，弱正 RankIC 已经更适合解释为“排序有一定参考价值”，不能解释为“能准确预测收益率”。

## 10. 什么是 PROMETHEE

`PROMETHEE` 是一种多属性决策方法。名字看起来复杂，但思想很直观：

> 不只看一个指标，而是把多个指标放在一起，两两比较股票，判断哪只股票整体更有投资前景。

它的流程可以理解为：

1. 选定一组评价指标；
2. 给每个指标分配权重；
3. 对股票进行两两比较；
4. 计算正流 `phi_plus`；
5. 计算负流 `phi_minus`；
6. 计算净流 `net_flow`；
7. `net_flow` 越高，投资前景越好。

几个关键词：

| 概念 | 通俗解释 |
|---|---|
| 正流 `phi_plus` | 一只股票超过别人的程度 |
| 负流 `phi_minus` | 一只股票被别人超过的程度 |
| 净流 `net_flow` | 综合优势，等于正流减负流 |

如果一只股票在多个指标上经常优于其他股票，它的正流会比较高；如果它经常被其他股票超过，负流会比较高。净流越高，说明综合评价越好。

## 11. 什么是熵权法

熵权法是一种自动确定指标权重的方法。

它的直观思想是：

> 一个指标在股票之间差异越大，说明它越能区分股票，就给它更高权重；如果一个指标大家都差不多，它区分度低，权重就低。

举例来说：

- 如果某个指标所有股票都差不多，那它很难帮助我们区分股票；
- 如果某个指标在不同股票之间差异很大，它可能更有筛选作用。

本项目中，熵权法不使用 `future_return_1q`。它只看指标自身在当期股票之间的离散程度，因此不会泄漏未来收益。

最终配置中，熵权方法是：

```text
entropy_weight_method = smooth_80_20
```

意思是把正常熵权和等权做平滑混合。这样做的好处是：

> 避免某一个指标因为短期差异很大而获得过高权重。

## 12. 本项目 PROMETHEE 的指标从哪里来

本项目不是随便把 231 个因子全部扔进 PROMETHEE。

PROMETHEE 的指标主要来自：

> 前向分步回归筛选出的高频因子或当前窗口入选因子。

这样做有几个原因：

1. 保持 PROMETHEE 和前向分步回归主线一致；
2. 避免 231 个因子全部进入导致噪声过大；
3. 提高解释性；
4. 让多属性评价建立在动态变量选择结果上。

最终配置中：

```text
promethee_top_n = 20
min_selected_count = 2
sign_stability_threshold = 0.55
```

这表示 PROMETHEE 会优先使用入选频率较高、方向相对稳定的一批因子。如果严格条件导致指标过少，程序会自动放宽条件，而不是直接报错。

## 13. PROMETHEE 为什么选择这个偏好函数

PROMETHEE 不只是“把指标加权平均”。它还需要定义一个问题：

> 股票 A 在某个指标上比股票 B 好多少，才算 A 对 B 有偏好？

这个规则叫“偏好函数”。

本项目最终配置中采用：

```text
preference_function = linear
```

也就是带无差异阈值的线性偏好函数。它和 V-shape / 线性偏好函数的思想非常接近：

> A 比 B 高一点点，就只给一点优势；A 比 B 高很多，才给很强优势。

### 13.1 通俗解释

普通偏好函数像是：

> 只要 A 比 B 高一点点，就直接判定 A 完全胜出。

线性偏好函数像是：

> A 比 B 高一点点，就只给一点优势；A 比 B 高很多，才给很强优势。

在股票因子数据中，后者更合理。因为两个股票某个因子相差 `0.01` 和相差 `2.00`，显然不应该被视为同等程度的优势。

### 13.2 本项目实际公式

代码实际采用的是带无差异阈值 `q` 的 Linear Preference Function。

设：

```text
d = g_j(a) - g_j(b)
```

其中：

- `g_j(a)` 表示股票 a 在指标 j 上的标准化得分；
- `g_j(b)` 表示股票 b 在指标 j 上的标准化得分；
- `d` 表示股票 a 相比股票 b 的指标优势。

线性偏好函数为：

```text
P_j(a,b) = 0, 如果 d <= q

P_j(a,b) = (d - q) / (p - q), 如果 q < d < p

P_j(a,b) = 1, 如果 d >= p
```

其中：

- `P_j(a,b)` 表示股票 a 相对于股票 b 在指标 j 上的偏好强度；
- `q` 是无差异阈值；
- `p` 是完全偏好阈值；
- `d <= q` 时，认为差异太小，可以忽略；
- `d >= p` 时，认为优势已经足够明显；
- `P_j(a,b)` 的取值范围是 0 到 1。

本项目代码中的实际参数是：

```text
q = 0.05
p = 0.25
sigma = 0.20
```

其中 `sigma` 只用于 Gaussian Preference Function，高斯偏好函数；最终 linear 偏好函数不使用 `sigma`。

这些阈值作用在已经做过缩尾、方向调整和 0-1 归一化后的 PROMETHEE 指标上。因此 `p = 0.25` 可以理解为：

> 当两个股票在某个指标上的归一化差距达到 0.25 或以上时，就认为优势已经比较明显。

### 13.3 与其他偏好函数相比有什么区别

| 偏好函数 | 通俗解释 | 在本项目中的特点 |
|---|---|---|
| Usual 普通偏好函数 | 只要 A 比 B 好一点点，就认为 A 完全胜出 | 太粗糙，容易放大极小差异 |
| U-shape U 型偏好函数 | 小差异忽略，超过阈值就完全偏好 | 能忽略小噪声，但仍然是跳跃式判断 |
| V-shape V 型偏好函数 | 差一点给小优势，差很多给大优势 | 能保留连续差异，解释清楚 |
| Level 分级偏好函数 | 小差异 0，中等差异 0.5，大差异 1 | 比普通偏好稳健，但仍然比较粗 |
| Linear 线性偏好函数 | 很小差异忽略，中等差异按比例加分，大差异满分 | 本项目最终配置采用，兼顾连续差异和小噪声过滤 |
| Gaussian 高斯偏好函数 | 偏好强度按平滑曲线增加 | 平滑，但 `sigma` 参数不如 q/p 直观 |

### 13.4 本项目数据上的敏感性比较

| usual | -0.1287 | -3.87% | -0.1478 | -19.04% | 0.5500 | -8.4238 | 0.5500 |

| v_shape | -0.1166 | -16.73% | -0.5514 | -21.01% | 0.3750 | -7.3078 | 0.9375 |

因此，本文最终保留 `linear` 偏好函数，主要原因是：

- 它符合连续型股票因子的特点；
- 它不会把极小差异直接放大成完全偏好；
- q 和 p 参数含义比 Gaussian 的 sigma 更容易解释；
- 它与优化流程中的最终配置一致；
- 它适合作为课程报告中可复现、可说明的 PROMETHEE 主方案。

同时也要如实说明：

> 偏好函数敏感性实验显示，单独使用 PROMETHEE 的排序表现并不强，因此 PROMETHEE 更适合作为多属性投资前景评价和解释工具，而不是替代前向分步回归主线。

## 14. 什么是 Hybrid Score

Hybrid Score 是把两种信息融合起来：

1. 前向分步回归：偏统计预测和排序；
2. PROMETHEE：偏多属性综合评价和可解释性。

以 `hybrid_score_50_50` 为例：

```text
hybrid_score_50_50
= 0.5 × promethee_rank_pct
+ 0.5 × stagewise_rank_pct
```

其中：

- `promethee_rank_pct`：PROMETHEE 分数在本季度的排名分位数；
- `stagewise_rank_pct`：前向分步回归预测分数在本季度的排名分位数；
- 分数越高，股票越靠前。

本项目比较了以下几种分数：

| 名称 | 含义 |
|---|---|
| `pure_stagewise_score` | 只使用前向分步回归排序 |
| `pure_promethee_score` | 只使用 PROMETHEE 排序 |
| `hybrid_score_70_30` | 70% PROMETHEE + 30% 前向分步回归 |
| `hybrid_score_50_50` | 50% PROMETHEE + 50% 前向分步回归 |
| `hybrid_score_30_70` | 30% PROMETHEE + 70% 前向分步回归 |

为什么要比较不同权重？

因为一开始我们不知道应该更相信统计模型，还是更相信多属性评价。用验证集比较，可以减少主观拍脑袋。

当前最终 Top-K 主方案选择的是：

```text
hybrid_score_name = pure_stagewise_score
top_k = 20
```

这并不意味着 PROMETHEE 没有用，而是说明在本次验证集选择规则下，最终组合回测更适合采用前向分步回归排序；PROMETHEE 仍然用于投资前景评价、解释、评级对比和 Hybrid 候选方案比较。

## 15. 为什么不能直接选测试集最好的方案

测试集相当于期末考试。

如果我们看了测试集结果再改模型，就等于：

> 先看答案，再回头改作业。

这会造成过拟合，也就是模型看起来在测试集很好，但其实只是迎合了这一次测试样本。

本项目严格区分：

- `train`：用于模型训练；
- `valid`：用于参数选择；
- `test`：用于最终 holdout 检验。

测试集不能用来调参数。如果测试集表现不好，也必须如实报告，不能删掉失败实验。

最终配置文件中也明确写明：

```text
selection_basis = max valid_score among valid-positive Top20/Top30 candidates; test metrics not used for selection
```

## 16. Top-K 回测是什么

Top-K 回测就是：

> 每个季度选综合评分最高的 K 只股票，假设等权买入并持有到下一期，看组合表现如何。

本项目比较过：

- Top10；
- Top15；
- Top20；
- Top30；
- Top50。

这里的 K 是持仓股票数量。

举例来说：

- Top10：每季度买评分最高的 10 只股票；
- Top20：每季度买评分最高的 20 只股票；
- Top30：每季度买评分最高的 30 只股票。

不同 K 的特点：

| K | 特点 |
|---|---|
| Top10 | 集中度高，可能收益高，但受个股偶然波动影响大 |
| Top20/Top30 | 相对均衡，既保留信号，又有一定分散度 |
| Top50 | 更分散，但可能把信号稀释 |

本项目最终选择 Top20，是因为课程项目更看重稳健性、分散度和解释性，而不是只追求验证集中最漂亮的 Top10 收益。

## 17. 绩效指标怎么理解

### 17.1 持有期收益率

持有期收益率就是：

> 这期买入，下一期卖出，赚了多少。

本项目按季度选股，所以它表示一个季度持有期内的组合收益。

### 17.2 年化收益率

年化收益率就是：

> 把季度收益换算成一年收益，方便不同策略比较。

它不是说每年一定能赚这么多，而是把样本期收益按一年尺度表示。

### 17.3 年化波动率

年化波动率表示：

> 收益上下波动的幅度。

波动率越高，说明组合收益越不稳定，风险越大。

### 17.4 Sharpe Ratio

Sharpe Ratio 可以理解为：

> 每承担一单位风险，能获得多少收益。

一般来说，Sharpe 越高越好。但如果样本季度很少，Sharpe 也可能不稳定。

### 17.5 Alpha

Alpha 表示：

> 相对于基准组合多赚的部分。

如果没有外部市场指数，本项目使用当期股票池等权平均收益作为 benchmark，也就是基准。

Alpha 为正，说明组合相对这个基准有超额收益。

### 17.6 Beta

Beta 表示：

> 组合对基准波动的敏感程度。

如果 Beta 较高，说明组合更容易跟着市场一起涨跌。

### 17.7 最大回撤

最大回撤表示：

> 从历史最高点到之后最低点，亏损最多的幅度。

例如最大回撤为 `-7%`，表示组合净值曾经从高点跌下去最多约 7%。最大回撤越小，风险越可控。

### 17.8 换手率

换手率表示：

> 本季度和上季度持仓变化程度。

换手率高，意味着交易更频繁；换手率低，说明持仓更稳定。

## 18. 13 级评级怎么构造

评级的作用是把连续评分转成更容易理解的等级。

本项目每个季度内，把股票按最终综合评分从高到低排序，然后分成 13 个等级：

```text
AAA, AA+, AA, AA-, A+, A, A-, BBB+, BBB, BBB-, BB+, BB, B
```

其中：

- `AAA` 是评分最高的一组；
- `B` 是评分最低的一组；
- 每个季度单独排序和分组；
- 不跨季度混合排序；
- `future_return_1q` 只用于事后检验，不参与评级生成。

评级不是保证：

> AAA 一定涨得最多，B 一定跌得最多。

更合理的理解是：

> 高评级组整体上更适合作为候选池，低评级组整体上相对不优先。

## 23. 老师可能会问的问题与回答

### Q1：为什么作业要求 276 个因子，你只用了 231 个？

因为实际数据中宏观因子只有 11 个可识别变量，且部分个股字段是收益类字段，不能入模。231 是在防止泄漏和保证可复现前提下的实际实现。

如果硬凑第 12 个宏观因子，或者把收益类字段放进解释变量，会破坏模型可信度。

### Q2：为什么不用所有因子，而要前向分步回归筛选？

因为因子太多会导致过拟合和解释困难。前向分步回归可以动态筛选当前滚动窗口中更有用的因子，让模型更简洁、更容易解释。

### Q3：R² 是负的怎么办？

股票收益点预测噪声很大，R² 弱很常见。本项目重点不是精确预测收益率，而是排序和组合检验，因此更关注 RankIC、Top-K 收益、评级分层和风险收益指标。

R² 弱不能说明模型一定没用，但也不能把弱排序信号夸大成强预测能力。

### Q4：PROMETHEE 和前向分步回归有什么区别？

前向分步回归是统计变量选择和预测排序方法；PROMETHEE 是多属性综合评价方法。

前者偏数据拟合，回答“哪些因子对收益排序更有帮助”；后者偏决策解释，回答“从多个指标综合看，哪只股票投资前景更好”。

### Q5：Hybrid Score 为什么合理？

Hybrid Score 把前向分步回归的统计排序信号和 PROMETHEE 的多属性评价信号融合，兼顾预测能力和可解释性。

不过本次最终 Top-K 主方案选择的是 `pure_stagewise_score_top20`。这说明在验证集选择规则下，前向分步回归排序更适合作为最终组合评分；PROMETHEE 和 Hybrid 仍作为解释和候选方案比较的重要组成部分。

### Q6：评级不完全单调是不是失败？

不是。评级用于候选池筛选，不是保证每一级收益严格递减。股票收益受噪声影响，高评级组整体更有投资前景即可。

本项目中，valid 和 test 的高评级组整体优于低评级组，说明评级有一定筛选价值；但不能说 AAA 一定比 AA、A、BBB 每一级都更高。

### Q7：为什么不能根据测试集最优结果选方案？

因为测试集是最终考试，用它调参会造成过拟合。最终方案必须根据训练集和验证集选择，测试集只用于最终检验。

### Q8：为什么 PROMETHEE 选择 linear 偏好函数？

因为股票因子是连续变量，差异有大小之分。Linear 偏好函数不会因为极小差异就给满分，也不会完全忽略中等差异，参数 q 和 p 也比较容易解释。

同时，偏好函数敏感性实验显示 PROMETHEE-only 排序并不强，因此本文把 PROMETHEE 定位为多属性评价和解释工具，而不是替代前向分步回归主线。

### Q9：为什么最终不是 Top10？

Top10 持仓太集中，单只股票权重为 10%，容易受到个别股票偶然表现影响。Top20 单只股票权重约 5%，更适合作为课程作业主方案，兼顾信号强度和分散度。

### 24.1 最优算法配置

最终算法配置来自 `outputs_optimized/final_selected_algorithm_config.json`。

| 参数 | 最终取值 | 含义 |
|---|---:|---|
| `rolling_window` | 12 | 每次使用过去 12 个季度作为训练窗口 |
| `max_selected_features` | 12 | 每个滚动窗口最多选择 12 个综合因子 |
| `selection_objective` | `residual_correlation` | 每一步优先选择最能解释残差的因子 |
| `refit_method` | `OLS` | 选出因子后用普通最小二乘回归重拟合 |
| `ridge_alpha` | 1.0 | Ridge 参数记录；最终重拟合方法为 OLS |
| `scaling_method` | `quarter_rank` | 每季度横截面排名标准化 |
| `winsorize_quantile` | 0.05 | 对极端值做 5%/95% 缩尾 |
| `feature_corr_threshold` | 0.90 | 对高度相关综合因子做过滤 |
| `promethee_top_n` | 20 | PROMETHEE 使用最多 20 个高频入选因子 |
| `entropy_weight_method` | `smooth_80_20` | 熵权与等权进行 80/20 平滑 |
| `preference_function` | `linear` | PROMETHEE 使用带无差异阈值的线性偏好函数 |
| `hybrid_score_name` | `pure_stagewise_score` | 最终 Top-K 主方案使用前向分步回归排序 |
| `top_k` | 20 | 每季度选前 20 只股票 |

这组参数不是随便选的，而是在训练集和验证集上比较后确定的。测试集只用于最后检验，不参与参数选择。

## 25. 当前模型的问题：为什么需要稳健优化

上一版模型已经完成 231 个宏微观综合因子、移动窗口前向分步回归、熵权-PROMETHEE、Hybrid Score、13 级评级和 Top-K 回测，但结果也暴露出几个问题。第一，测试集 RankIC 为正，说明模型确实有一定横截面排序能力；第二，测试集年化收益、Alpha 和 Sharpe 较弱，说明排序信号转化为真实组合收益的能力有限；第三，验证集明显好于测试集，说明参数对验证区间较敏感；第四，Top20 换手率偏高，如果考虑交易成本，真实收益可能进一步被压缩。

因此，本轮 v3 不是推翻原模型，而是在原主线下做稳健优化：降低模型复杂度，减少换手，关注 Alpha 稳定性和 valid/test 差距，而不是继续追求验证集收益最大化。

## 26. 稳健优化思路

稳健优化主要做了八件事：

1. 将 `max_selected_features` 降到 5、6、8、10，减少噪声因子进入模型；
2. 提高 `min_improvement`，要求新因子必须带来更明显边际改善；
3. 比较 OLS 和 Ridge，降低小样本窗口下的系数波动；
4. 统计稳定因子池，测试期优先使用更稳定的因子；
5. 比较 Top20、Top30、Top50，不再强制 Top20；
6. 加入 buffer rule，降低持仓频繁进出；
7. 加入 rank smoothing，只用过去评分平滑当前评分；
8. 使用 `robust_valid_score`，提高 RankIC、ICIR、Alpha、Information Ratio 的权重，同时惩罚换手率和回撤。

整个过程仍然只用 train 和 valid 做参数选择，test 只用于最终 holdout 检验。

## 30. 换手率与交易可实现性

原模型 Top20 换手率偏高，说明每个季度持仓变化较大。即使回测没有计入交易成本，真实交易也会受到佣金、冲击成本和买卖价差影响。

v3 加入 buffer rule：Top30 下，新买入需要进入 Top25，原持仓只要仍在 Top40 内就保留；Top20 下，新买入需要进入 Top15，原持仓仍在 Top30 内就保留。这个规则的目标是减少因为排名小幅波动造成的频繁交易。

## 32. PROMETHEE 偏好函数选择与数据比较

稳健版本继续采用 PROMETHEE 作为多属性投资前景评价工具。最终偏好函数为 `linear`。本项目重点解释 linear preference function：

设 `d = g_j(a) - g_j(b)`，其中 `g_j(a)` 是股票 a 在指标 j 上的标准化得分，`g_j(b)` 是股票 b 在指标 j 上的标准化得分。

Linear Preference Function 为：

```text
P_j(a,b) = 0, 如果 d <= q
P_j(a,b) = (d - q) / (p - q), 如果 q < d < p
P_j(a,b) = 1, 如果 d >= p
```

本项目默认 `q = 0.05`，`p = 0.25`，`sigma = 0.20`。其中 sigma 只用于 Gaussian 对照，linear 不使用 sigma。

linear 偏好函数适合本项目，是因为综合因子经过标准化后是连续变量。两个股票之间差距很小时，不应该直接判定一方完全胜出；差距逐渐变大时，偏好强度也应该逐渐增加。

## 33. 稳健优化后的结论

稳健优化后的结论应根据实际指标谨慎表述。如果测试集收益、Alpha、Sharpe 或 Information Ratio 改善，同时换手率下降，可以写“样本外稳定性有所提升”。如果收益没有明显提升，但换手或回撤下降，可以写“模型更适合作为候选池筛选和投资前景评价框架”。如果测试集仍然较弱，则必须如实说明现有因子体系在测试期的收益转化能力有限。

本项目不能宣称模型可以准确预测未来收益率，也不能宣称策略稳定盈利。更合适的最终表述是：v3 稳健优化在保持前向分步回归主线的基础上，系统检查了模型复杂度、Ridge 稳健重拟合、稳定因子池、排名平滑、buffer rule、Alpha 稳定性和 PROMETHEE 偏好函数敏感性，使模型解释和风险检验更完整。
